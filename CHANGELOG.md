# Changelog

Notable changes to Model2API, the web and the desktop version together. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/) and versions follow [Semantic Versioning](https://semver.org/). Desktop releases will be tagged `v<version>` and published on [Releases](https://github.com/RaulEstevezA/Model2API/releases).

## [Unreleased]

### Added

- Web: reads models in 23 formats with the importers of Mapper (code in 12 languages, JSON Schema, OpenAPI, GraphQL, Protocol Buffers, Smithy, Prisma, model schema, and JSON, YAML, XML or CSV documents), and the validations each field declares: Jakarta Bean Validation, class-validator, DataAnnotations, Symfony Validator, Laravel Data and Laravel rules, Pydantic, Django, JPA, SQLAlchemy, Prisma, Zod, Go tags and JSON Schema.
- Web: proposes an API for the models, each proposal with its confidence and its reason: which models are resources and which travel inside others, the key of each resource, how related models travel (their key or the whole item), what clients may send or read of each field (keys and timestamps read only, secrets send only), and the six standard endpoints of each resource. What it is not sure about waits for the user and leaves a `TODO` in the code.
- Web: every decision and endpoint can be changed, with undo and redo: paths, operation names, summaries, status codes, who may call each endpoint (public, with credentials, some roles), pagination, filters and sorting of lists, and business endpoints that are not CRUD.
- Web: checks the design before writing code (routes that clash, paths without the key, filters on fields that cannot be filtered…); an endpoint with an error is left out and the reason is shown.
- Web: writes the OpenAPI 3.1 contract of the API, the same for every framework.
- Web: writes projects for FastAPI, Django REST Framework, Express, NestJS and Spring Boot, by layers or one folder per resource, with storage in memory, as interfaces to implement, or with SQLAlchemy, the Django ORM, TypeORM or JPA on PostgreSQL, MySQL, MariaDB or SQLite; authentication with an API key or JWT with roles; one error format; validations with each framework's own tools; tests that call every endpoint; README and `.env.example`.
- Web: only offers stacks that have been verified by building, running and testing generated projects in Docker.
- Web: browse, copy and download each generated file, the OpenAPI contract, or the whole project as a .zip.
- Web: three built-in examples, project files to save and open, and "Remember in this browser".
- Web: the page of the tool, in English and Spanish, following the layout of the other tools.
- Web: writes Laravel 13 projects (PHP 8.3+), by layers or one folder per resource, with storage in memory, as interfaces to implement, or with Eloquent on PostgreSQL, MySQL, MariaDB or SQLite; Form Requests that reject unknown fields and check blank texts that Laravel's own rules let through; API key or JWT with roles; PHPUnit tests that call every endpoint. Verified in Docker with every storage and database.
- Web: writes Symfony 8.1 projects (PHP 8.4+), by layers or one folder per resource, with storage in memory, as interfaces to implement, or with Doctrine ORM on PostgreSQL, MySQL, MariaDB or SQLite; request bodies checked with Symfony Validator collections that reject unknown fields and blank texts the format constraints let through; API key or JWT with roles; PHPUnit tests that call every endpoint. Verified in Docker with every storage and database.
- Web: writes ASP.NET Core projects (.NET 10), by layers or one folder per resource, with storage in memory, as interfaces to implement, or with Entity Framework Core on PostgreSQL, MySQL, MariaDB or SQLite; request bodies that reject unknown fields and tell a missing field from one sent as null, strict JSON enums, API key or JWT with roles; an xUnit test project that calls every endpoint. Verified in Docker with every storage and database.
- Web: writes Ktor projects (Kotlin 2.4, Gradle), by layers or one folder per resource, with storage in memory, as interfaces to implement, or with Exposed on PostgreSQL, MySQL, MariaDB or SQLite; request bodies checked on their JSON before they are read (presence, null, types, lengths, ranges, patterns), API key or JWT with roles; tests on ktor-server-test-host that call every endpoint. Verified in Docker with every storage and database.
- Web: writes Axum projects (Rust 1.99, edition 2024, Cargo), by layers or one folder per resource, with storage in memory, as traits to implement, or with SeaORM on PostgreSQL, MySQL, MariaDB or SQLite; request bodies checked on their JSON before they are read (presence, null, types, lengths, ranges, patterns), API key or JWT with roles; integration tests that call every endpoint through the router. Verified in Docker with every storage and database, with every compiler warning treated as an error.
- Web: writes Vapor 4 projects (Swift 6.4, Swift Package Manager), by layers or one folder per resource, with storage in memory, as protocols to implement, or with Fluent on PostgreSQL, MySQL, MariaDB or SQLite; request bodies checked on their JSON before they are decoded (presence, null, types, unknown fields, lengths, ranges, patterns), 405 for a method a path does not take, API key or JWT with roles; Swift Testing suites that call every endpoint. Verified in Docker with every storage and database, without warnings in the project's code.
- Desktop: the same tool as a Python + PySide6 app for macOS, Windows and Linux: the same importers, proposals, checks, OpenAPI contract and generators, which write exactly the same files as the web version for the shared cases; the models, endpoints and project panes; project files, "Remember on this computer", and saving files, the contract or the whole project as a .zip.
